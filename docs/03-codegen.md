# Code Generation

## Overview

Kapila compiles to C code, which is then compiled to native executables using a C compiler (TinyCC or GCC).

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌────────────┐
│ Kapila      │     │ C Code      │     │ Native      │     │ Executable │
│ Source      │ ──▶ │ Generator   │ ──▶ │ C Compiler  │ ──▶ │ (.exe)     │
│ (.kpl)      │     │             │     │ (tcc/gcc)   │     │            │
└─────────────┘     └─────────────┘     └─────────────┘     └────────────┘
```

## Why C Instead of LLVM?

| Aspect | C Codegen | LLVM Codegen |
|--------|-----------|--------------|
| Complexity | ~300 lines | ~1000+ lines |
| Dependencies | Just gcc/tcc | llvmlite + LLVM (~500MB) |
| Debugging | Read the .c file | Binary IR |
| Portability | Any C compiler | LLVM version issues |
| Distribution | 18MB with TinyCC | 500MB+ with LLVM |

C was chosen for simplicity and ease of distribution. LLVM remains a future option.

## Generated Code Structure

For a simple Kapila program:

```
// hello.kpl
ವರ್ಗ: ನಕಲು ಗುಣಿಸು ॥
೫ ವರ್ಗ ಮುದ್ರಿಸು.
```

The generator produces:

```c
/* Generated by Kapila Compiler */
#include "kapila.h"

/* === User-defined words === */

void word_ವರ್ಗ(void) {
    dup_op();
    mul_op();
}

int main() {
    kapila_init();

    push_int(5);
    word_ವರ್ಗ();
    println_op();

    kapila_cleanup();
    return 0;
}
```

## Code Generator Implementation

The code generator (`src/codegen/c_generator.py`) uses the visitor pattern:

```python
class CGenerator(NodeVisitor):
    def visit_NumberLit(self, node):
        self._emit(f'push_int({node.value});')

    def visit_Word(self, node):
        if node.name in self.builtins:
            self._emit(f'{self.builtins[node.name]}();')
```

## Name Mangling

Kannada identifiers are converted to valid C identifiers:

```
ವರ್ಗ  →  word_ವರ್ಗ (with hex encoding for non-ASCII)
```

## Supported Features

| Feature | C Code Generated |
|---------|------------------|
| Numbers | `push_int(n)` / `push_float(f)` |
| Strings | `push_str("...")` |
| Booleans | `push_bool(true/false)` |
| Arithmetic | `add_op()`, `sub_op()`, etc. |
| Comparison | `lt_op()`, `gt_op()`, `eq_op()` |
| Stack ops | `dup_op()`, `swap_op()`, `drop_op()` |
| Word defs | C functions |
| Lists | `list_new()`, `list_push_item()` |
| Print | `println_op()` |

## Runtime Library

The generated code depends on the runtime library (`runtime/kapila.h` and `runtime/kapila.c`) which provides:

- Value type with union (int, float, bool, string, list)
- Stack operations
- All built-in operations
- Memory management
